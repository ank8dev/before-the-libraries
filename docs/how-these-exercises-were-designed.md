# How these exercises were designed

## Honest note about the research
I did 4 web searches. I could not open the CS50P and CS231n pages (blocked). I read only search summaries. I did not research MIT 6.100L, fast.ai, CS224n, CS229, or retrieval practice. I found no source for predict-then-run.

## What the sources said
- Karpathy's makemore starts with a bigram count table. One summary shows a dictionary tally with `.get`. This supports tasks 9 and 10.
- A CS231n tutorial mirror covers lists, dicts, functions and classes first. Then it covers array shape and transpose. This supports the order of Block 1 and Block 4.
- A Raspberry Pi summary of research says that solving with no guidance puts heavy load on novices. Worked examples can help them start. But examples alone may not help them remember. So each task has an example, and also a question to answer first.
- The CS50 FAQ says check50 shows which tests fail. So each file has plain `assert` checks.

## Design rules I used
1. One task, about one new idea.
2. A small example in every task.
3. A question to answer before you run the code.
4. Exact search terms, so you do not google everything.
5. Three hints, from small to big. Concepts only, no code.
6. Checks with edge cases that teach something.
7. Library link only after you finish.

## What changed in the task list
Nothing. I kept all 15 tasks and their order. No source I read gave a reason to change them.
